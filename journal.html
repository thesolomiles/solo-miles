2026-09-20 · Sunday

  • Built a chibi road bike + a real cycling animation for the ride scene (until now riders just ran-in-place). Modelled a low-poly road bike — drop bars, diamond frame, thin spoked wheels, saddle — in chibi proportions to fit the existing player: short wheelbase, low bottom bracket and a short crank so the character's stubby legs reach the full pedal circle without the knee locking. On the shared Imphenzia palette (teal frame, black tires, grey rims/cranks), so it reads as one set with the town.
  • The existing rig already cycles — no re-rig needed. The player armature has leg IK with foot goals (IKTarget.L/R + knee poles IKPole.L/R), which is exactly what a crank-driven pedal loop wants. Approach: the crank + pedals are one object spinning about the bottom bracket; pedal-empty children drive the foot IK goals (copy-location), so the feet ride the pedals and the IK solves the knees. Wheels spin 3× the crank, all on one linear 24-frame loop. Seated the character first (hands on bars via a temporary 2-bone arm IK, slight forward lean), then baked the IK to bone keyframes for export.
  • Picked the simplest/canonical character (the base playable player — lowest tri count, on the master palette material) and duplicated it so the 8 town rigs stay untouched; the cyclist stays visually identical to the player for consistency.

  • Revision pass (looked wrong first cut). Fixed five things to make it read as a proper cyclist: (1) removed the pedals (never visible); (2) the earlier "only the left leg pedals" bug — I'd nudged both foot goals +0.045 in Z, which shrank the down-pedal's orbit radius to ~0.02 and grew the up-pedal's to ~0.11; placing the goals exactly on the crank-arm ends makes both legs symmetric (both feet travel 0.13, knees swing a healthy 91°→142°, no lock); (3) much stronger forward crouch (Spine ~-46°, head up) instead of sitting upright; (4) hands now actually grip the bars — the chibi's short arms (reach 0.72) couldn't span the 0.94 to the old bars, so the rider was moved forward and the whole front end rebuilt compact (bars/stem/head-tube/front-wheel pulled back to a reachable, natural bent-arm grip); (5) re-baked + re-exported. Lesson: fit the cockpit to the chibi's reach, don't scale a realistic road bike down.
  • Second revision — "who rides a bike like this?" The compact cockpit still sat too upright. Rebuilt to a real road stance: saddle setback (hips behind the BB), low forward drop bars, longer front-centre — and an aggressive forward lean (torso ~26° above horizontal) with the head lifted to look up the road, so it reads like the reference racer. The reach works because a hard lean throws the shoulders far forward, so low-forward bars come back into range. Also: deep-section carbon rims (deep V annulus, not a thin hoop) and a dark-grey carbon frame/cranks with black bar-tape + saddle. Legs stayed symmetric (both feet 0.13, knees 95°→151°). Gotcha: pose-bone rotation is in bone-local space — the spine's forward lean is a positive X rotation here, not negative; I'd had the sign inverted, which is why earlier "leans" barely tipped forward. Measure shoulder Y against hip Y to confirm the direction before committing.
  • Cadence + bob. Set the pedalling to 85 rpm — one crank revolution per 24-frame loop, exported at 34 fps so the clip is 0.706 s/rev = 85.0 rpm (wheels stay 3× the crank). Added a very slight upper-body bob: a 2-per-revolution ±2° pitch on the upper spine with the head counter-rotated ~±1° so the gaze holds steady — reads as effort, not a wobble. Baked with the arm IK live so the hands stay planted on the bars through the bob (verified max 0.01 drift). Note: cadence is controlled purely by the exported clip duration, so it's set via scene fps at export, not by re-timing keyframes.

Each patron is its own GLB and they preload on module load — ten maps × ten unique NPCs × preload-everything is how the homepage dies on a phone. Keep one Canvas, swap the world, dispose shadows/env maps, don't keep town mounted under the café, don't merge maps into one mega GLB.
    • NPCs. A few Mixamo clones are cheap. What scales badly: one GLB per character, unique skeletons/mixers on every body, everyone casting VSM shadows, preloading NPCs for maps you haven't entered. Share one rig, recolour/swap meshes, instance idle sitters, animate what's on screen, no per-NPC lights.
    • Minigames. Pac-Man is the right shape (same camera, same character, town unmounted). Don't treat each game as a mini engine, and don't leave café + maze both rendering.
    • Phones. iOS already can't run the composer (black blobs). Every new map/minigame needs an iPhone pass, not just ?debug on the Studio.
    • Store. Checkout as HTML on a paused or DPR-dropped scene, not a 3D register. Stripe (or similar); inventory/shipping/tax/returns matter more than merch crates in the GLB. Don't preload the catalogue into WebGL.
    • Cheap insurance. Cap DPR on large screens; stop preloading unused maps/NPCs; keep one shared character pipeline; pause the WebGL loop on the shop and when the tab is hidden.
